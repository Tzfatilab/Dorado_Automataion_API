# R Dependency Classification

This document records dependencies for both `dorado_workflow/data/NanoTel.R` and the shipped scripts
under `dorado_workflow/r_analysis/`. It separates direct runtime requirements from packages supplied
by R, transitive dependencies, packages awaiting team classification, and representative execution
tests that have not yet been supplied.

## NanoTel.R

### Accepted Direct Dependencies

| R library | Conda package | Process supported |
| --- | --- | --- |

| `purrr` | `r-purrr` | Build the current telomere-pattern parser with `compose()` and `partial()`. |
| `stringr` | `r-stringr` | Inspect, split, and manipulate pattern strings. |

| `future` | `r-future` | Select multicore or multisession execution plans. |
| `logr` | `r-logr` | Create and write the NanoTel run log. |
| `ggprism` | `r-ggprism` | Style the plot generated by the approved optional `--analysis` process. |

`r-survival` is installed now even though `include_km_metrics` is currently `FALSE`. This avoids a
future feature activation that forgets its runtime dependency. Its presence does not approve the KM
statistics.

### Supplied Or Transitive

- `parallel` is required by NanoTel but is supplied with R, so the recipe does not list a separate
  Conda package.
- `tibble` is installed transitively by accepted packages such as `dplyr` and `readr`. NanoTel has no
  confirmed direct use that requires a separate recipe entry.
- The `%>%` operator is available through the accepted tidyverse component dependencies; no separate
  direct `magrittr` declaration is currently needed.

### Not Direct NanoTel Dependencies For Now

- `tidyverse` is an umbrella package and is intentionally not declared directly. NanoTel's actual
  component dependencies are listed individually.
- `tidyr`, `forcats`, and `lubridate` have no confirmed active NanoTel calls. Do not interpret this as
  removal from the entire project: `r-tidyr` is still required by the separate core R-analysis code.

No change to `NanoTel.R` has been approved to remove or replace its current `require(tidyverse)` and
fallback package-loading block. The dependency decision and source cleanup decision remain separate.

## r_analysis Runtime Scripts

The shared `load_required_packages()` function currently attempts to install and load thirteen CRAN
packages for every analysis run. `main_analysis_pipeline.R` also loads `jsonlite`. The Bioconda draft
lists all fourteen packages so that an installed workflow does not download packages at runtime.

### Runtime Dependency Policy

`functions/utils.R` does not download packages while the workflow is running. If a declared R
dependency is missing, it stops with a message listing the missing packages and instructing the user
to repair the Conda environment. This keeps dependency versions under Conda's control and allows the
workflow to run without internet access. A packaged-resource test protects this policy.

## Representative Execution Test Status

Sanitized team-supplied FASTQ and BAM fixtures and a gated integration test now cover NanoTel
`--summary_only`, active `--analysis` output generation, NanoTel filtration, aligned-BAM summary
generation, mapping, BAM filtering, and the absence of methylation tags. On 2026-08-05, the original
three tests passed in an isolated Linux
Micromamba environment containing the dependency set declared by the draft recipe. On 2026-08-06,
they passed both conda-build's installed-package tests and an independent clean installation of the
built package. Approved scientific regression values are recorded in
`tests/fixtures/integration/expected_results.json`; build details are in
`BIOCONDA_BUILD_REHEARSAL.md`. On 2026-08-09, the extended suite including the new `--analysis`
assertions passed in 73 seconds in a fresh Linux environment containing the recipe's declared R
dependencies. The next package build will repeat these assertions against the installed package.

The analysis assertion is a structural smoke test based on five detected reads and one final row. It
does not validate a scientific estimate. KM metrics remain in progress and are explicitly outside
the test.

Additional test coverage is still needed for:

1. Reverse complement, filtering, and TVR patterns when the
   supplied fixtures support those paths.
2. A BAM containing approved modified-base tags for actual methylation analysis.

Verify successful exit, expected summary/read-ID outputs, expected `--analysis` outputs, and absence
of missing-function or missing-package failures. The clean test environment must omit the direct
`r-tidyverse`, `r-forcats`, and `r-lubridate` packages. `tibble` may still be installed transitively.

Future fixtures should also cover optional static plots, optional interactive HTML, and an optional
generated Shiny app according to the features the team classifies as supported.
